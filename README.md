**How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?**

Interpreting user needs involves understanding what the users want to achieve and the problems they face. This often requires gathering feedback through interviews, surveys, or observing user interactions. Creating “user stories” helps because they translate these needs into clear, actionable items for the development team. User stories provide a simple and understandable format that outlines the user's goals and the value it brings, making it easier to prioritize and implement features that truly matter to the users.

When developing programs, I focus on iterative development, starting with a basic version of the product and gradually adding features based on user feedback. I hope to incorporate Agile processes like Scrum or Kanban, which emphasize regular updates, flexibility, and close collaboration with stakeholders.
